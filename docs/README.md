# LiftBook — сайт для GitHub Pages

Эта папка — готовый статический сайт. Его можно целиком загрузить на GitHub,
и GitHub Pages выдаст ссылку для скачивания приложения.

## Как выложить (3 шага)

1. Создай на GitHub новый репозиторий (например, `liftbook`).
   Публичный — тогда GitHub Pages будет бесплатным.

2. Загрузи в репозиторий **всю папку `docs`** так, чтобы в корне репозитория
   оказалась папка `docs`, а внутри неё — `index.html`, `LiftBook_2-8.apk`,
   `img/`, `fonts/`.

   В веб-интерфейсе GitHub: **Add file → Upload files**, перетащи папку `docs`
   целиком и нажми **Commit changes**.

   В репозитории должно получиться так:

   ```
   liftbook/                  ← репозиторий
   └── docs/
       ├── index.html        ← главная страница
       ├── LiftBook_2-8.apk
       ├── apk.sha256
       ├── 404.html
       ├── .nojekyll
       ├── fonts/
       └── img/
   ```

3. Открой **Settings → Pages**:
   - **Source**: `Deploy from a branch`
   - **Branch**: `main`
   - **Folder**: `/docs`
   - Нажми **Save**.

Через 1–2 минуты страница появится по адресу:

```
https://<твой-логин>.github.io/<имя-репозитория>/
```

Например, для логина `kalser` и репозитория `liftbook`:

```
https://kalser.github.io/liftbook/
```

Готово — ссылку можно отправлять друзьям, APK скачивается прямо с сайта.

## Если браузер не даёт перетащить папку

Загрузи **содержимое** папки `docs` (файлы `index.html`, `LiftBook_2-8.apk`,
`img/`, `fonts/`, `.nojekyll` и остальные) в корень репозитория. Тогда в
настройках Pages выбери папку `/ (root)` вместо `/docs`. Результат тот же.

Не называй репозиторий `<логин>.github.io`, если хочешь использовать папку
`/docs`: для пользовательского сайта GitHub Pages публикует только корень.
Для обычного репозитория (например, `liftbook`) папка `/docs` работает.

### Главное правило

Папка в **Settings → Pages** должна совпадать с тем, что реально лежит в
репозитории:

| Что загружено | Что выбрать в Pages |
|---|---|
| папка `docs`, внутри неё `index.html` | `/docs` |
| файлы `index.html`, `img/`, `fonts/` лежат прямо в корне | `/ (root)` |

Если перепутать, GitHub Pages покажет заглушку, 404 или страницу без
содержимого — хотя сам сайт полностью рабочий.

Если загрузить **весь проект LiftBook** целиком (а не только папку `docs`), в
корне проекта уже лежит `index.html`-перенаправление на `docs/index.html`.
Тогда сайт откроется и при выборе `/ (root)`, и при выборе `/docs`.

## Если на сайте видна только шапка

Почти всегда это значит, что GitHub Pages публикует не ту папку. Проверь по
порядку:

1. **Открой прямую ссылку на файл:**

   ```
   https://<логин>.github.io/<репозиторий>/index.html
   ```

   Если по ней открывается весь сайт, а по короткой ссылке — нет, проблема в
   настройке папки. Если и по прямой ссылке только шапка — значит, загрузился
   не тот `index.html` или страница ещё не пересобралась.

2. **Проверь дерево файлов в репозитории.** На GitHub открой вкладку **Code**:

   - если в корне репозитория лежит папка `docs`, а в ней `index.html` —
     в Pages должна быть выбрана папка **`/docs`**;
   - если `index.html` лежит прямо в корне репозитория (без папки `docs`) —
     в Pages должна быть выбрана папка **`/ (root)`**.

   Если выбрать `/docs`, а папки `docs` в репозитории нет, GitHub Pages покажет
   заглушку или 404 вместо сайта.

3. **Посмотри статус публикации:** **Settings → Pages**. Сверху должно быть
   написано **«Your site is live at …»** и время последнего деплоя. Если там
   «Your site is ready to be published» или ошибка — нажми **Save** ещё раз и
   подожди 1–2 минуты.

4. **Обнови страницу с очисткой кэша:** `Ctrl+Shift+R` на компьютере или
   открой ссылку в режиме инкогнито. GitHub Pages и браузер иногда держат
   старую версию.

5. **Проверь, что файлы закоммичены.** После **Upload files** нужно нажать
   **Commit changes**. Если файлы остались в разделе «Changes», сайт их не
   увидит.

6. **Проверь имя ветки.** В настройках Pages должна быть та ветка, куда ты
   загрузил файлы: обычно `main`, иногда `master`.

Если ничего не помогло — пришли ссылку на сайт и скриншот **Settings → Pages**,
тогда можно сказать точнее.

## Важно

- Не переименовывай папку `docs`: именно её GitHub Pages умеет публиковать
  без отдельной настройки сборки.
- Файл `.nojekyll` уже лежит внутри — он отключает обработку Jekyll и не даёт
  GitHub Pages что-либо потерять. Если при загрузке через браузер скрытый файл
  не попал в репозиторий, создай его вручную: **Add file → Create new file**,
  имя `.nojekyll`, содержимое пустое.
- Ограничения GitHub: до 1 ГБ на сайт и до 100 МБ на файл. APK весит ~11 МБ,
  так что всё помещается.
- APK лежит в репозитории открыто. Это нормально для бесплатного GitHub Pages,
  но не выкладывай туда ничего секретного.
- Подпись APK: постоянный release-ключ (RSA-4096, схемы v2 и v3). Сам ключ
  лежит вне `docs` — в `../keystore/ironlog-release.jks`, вместе с паролями в
  `../keystore/keystore.properties`. **Не теряй эти файлы**: без них обновления
  нельзя будет ставить поверх, и **не публикуй их** на сайте.
- Play Защита предупреждает про любой APK не из Google Play — это нормально.
  Подпись постоянным ключом делает обновления предсказуемыми, но полностью
  убирает предупреждение только публикация в Google Play.

## Что внутри

- `index.html` — сам сайт, без внешних зависимостей.
- `LiftBook_2-8.apk` — release-сборка приложения. В 2.8 исправлено дублирование в числовых полях: первая правка после нажатия заменяет старое значение один раз, затем backspace и ввод работают обычно. График прогресса строится по последним 30 тренировкам с упражнением, одна точка на тренировку. Сохранены импорт программ с весами из истории, компактная тренировка без недели и рутины, мелкие таймеры и длинный отдых 2:30. Есть чёрный и белый акценты, редактируемые фазы цикла, автопрогрессия и ежедневные напоминания. Отчёт о тренировке показывает веса (`50 кг × 6`) без кода `LIFTBOOK1:`, программы отправляются без весов.
- `apk.sha256` — контрольная сумма SHA-256 файла `LiftBook_2-8.apk`.
  На странице есть отдельный блок, который объясняет, зачем она нужна и как
  сверить файл на Windows, macOS, Linux или Android.
- `fonts/Neucha.ttf` — рукописный шрифт для обычных тем.
- `fonts/Caveat.ttf` — более живой рукописный шрифт тем «Синий почерк» и «Чёрный почерк».
- `img/` — иконка и скриншоты.
- `.nojekyll` — отключение Jekyll.
- `404.html` — страница на случай неверной ссылки.

## Проверка локально

```bash
cd /home/kalser/liftbook/docs
python3 -m http.server 8000
```

Открыть: <http://localhost:8000>

## Обновление версии

1. Собрать APK: `./gradlew assembleRelease`.
2. Скопировать `app/build/outputs/apk/release/app-release.apk` в
   `docs/LiftBook_<мажор>-<минор>.apk` (сейчас — `LiftBook_2-8.apk`).
3. Обновить ссылки, версию и SHA-256 в `index.html`.
4. Пересчитать сумму:

```bash
cd docs
sha256sum LiftBook_<мажор>-<минор>.apk > apk.sha256
```

5. Загрузить обновлённые файлы в репозиторий — GitHub Pages обновится сам.

## Альтернатива без настроек

Если GitHub Pages кажется слишком капризным, тот же сайт можно выложить на
**Netlify Drop** (<https://app.netlify.com/drop>): перетащи папку `docs` в
окно браузера — и через несколько секунд получишь готовую ссылку. Настройки
папок там не нужны.
